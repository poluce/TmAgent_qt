## 二、需求分析

### 2.1 为什么需要心跳

当前 TmAgent 的 Agent 是完全被动的——只有用户发消息才会触发响应。缺少：

1. **主动关怀**：Agent 无法主动联系用户（如晨间问候、定期签到）。
2. **后台维护**：记忆整理、文档更新等维护任务无法自动执行。
3. **健康监控**：无法感知 MCP 服务器、LSP 进程等外部依赖的存活状态。

### 2.2 为什么需要定时任务

心跳是粗粒度的周期性唤醒，但某些场景需要精确调度：

1. **精准时间点**：每天 9:00 晨间简报、每周一复盘。
2. **会话隔离**：定时任务应在独立会话中执行，不污染主对话。
3. **一次性提醒**：20 分钟后提醒我某件事。

### 2.3 与现有系统的关系

| 现有能力 | 心跳/定时任务的补充 |
|---------|-------------------|
| 记忆系统（M1-M4） | 心跳触发记忆整理/反思，定时任务触发记忆备份 |
| AgentEventBus | 心跳/任务事件接入统一事件流 |
| 工具循环熔断 | 心跳触发的 LLM 调用复用现有熔断策略 |
| 子代理委派 | 定时任务可委派给子代理执行 |
| MessageRouter | 群聊就绪后，心跳消息可路由到群聊 |

## 三、架构设计

### 3.1 总体架构

```
┌─────────────────────────────────────────────────┐
│                   ChatService                     │
│  ┌──────────────┐  ┌───────────────────────────┐ │
│  │ HeartbeatSvc  │  │     SchedulerService      │ │
│  │ (周期唤醒)    │  │     (精准调度)             │ │
│  └──────┬───────┘  └──────────┬────────────────┘ │
│         │                      │                   │
│         ▼                      ▼                   │
│  ┌─────────────────────────────────────────────┐  │
│  │          HeartbeatWake（请求合并层）           │  │
│  │          250ms 合并窗口 + 双重缓冲            │  │
│  └──────────────────┬──────────────────────────┘  │
│                     │                              │
│                     ▼                              │
│  ┌─────────────────────────────────────────────┐  │
│  │     AgentRuntime::handleHeartbeat()          │  │
│  │     复用现有 LLM 调用链路                      │  │
│  └─────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────┘
         │
         ▼
   AgentEventBus（heartbeat.triggered / heartbeat.completed /
                  scheduler.fired / scheduler.completed）
```

### 3.2 HeartbeatService — 周期唤醒服务

职责：管理每个 Agent 的心跳周期，触发主动唤醒。

```cpp
// src/core/service/HeartbeatService.h

class HeartbeatService : public QObject {
    Q_OBJECT
public:
    static HeartbeatService &instance();

    // 为指定 Agent 启动心跳
    void startHeartbeat(const QString &agentId);
    void stopHeartbeat(const QString &agentId);
    void stopAll();

    // 手动触发一次心跳
    void triggerHeartbeat(const QString &agentId, const QString &reason = "requested");

    // 运行时更新配置（热加载）
    void updateConfig(const QString &agentId, const HeartbeatConfig &config);

signals:
    void heartbeatTriggered(const QString &agentId, const QString &reason);
    void heartbeatCompleted(const QString &agentId, const QString &result);
    void heartbeatSkipped(const QString &agentId, const QString &reason);

private:
    struct AgentHeartbeat {
        HeartbeatConfig config;
        HeartbeatWake wake;          // 请求合并器
        QDateTime lastRunAt;
        QDateTime nextRunAt;
    };
    QHash<QString, AgentHeartbeat> m_agents;
};
```

### 3.3 HeartbeatWake — 请求合并器

职责：合并短时间内的多次唤醒请求，避免重复执行。

```cpp
// src/core/service/HeartbeatWake.h

class HeartbeatWake : public QObject {
    Q_OBJECT
public:
    explicit HeartbeatWake(QObject *parent = nullptr);

    void setHandler(std::function<void(const QString &reason)> handler);
    void setCoalesceMs(int ms);  // 默认 250ms

    // 请求一次执行（会被合并窗口延迟）
    void request(const QString &reason);

    // 取消所有待执行请求
    void cancel();

signals:
    void executed(const QString &reason);
    void skipped(const QString &reason);

private:
    void scheduleExecution();
    void executeHandler();

    std::function<void(const QString &)> m_handler;
    QString m_pendingReason;
    bool m_scheduled = false;
    bool m_running = false;
    int m_coalesceMs = 250;
    QTimer *m_timer = nullptr;
};
```

### 3.4 HeartbeatConfig — 心跳配置

```cpp
// src/core/model/HeartbeatConfig.h

struct ActiveHours {

    QTime end;            // 如 23:00（支持跨午夜）
```

### 3.6 ScheduledJob — 定时任务模型

### 3.7 Cron 表达式解析

采用 header-only 的 croncpp 库（MIT 许可），或自行实现简单的 5 段解析器。

5 段格式：`分 时 日 月 周`

```cpp
// src/core/utils/CronParser.h

class CronParser {
public:
    // 解析 cron 表达式，返回 after 之后的下一个触发时间
    static QDateTime nextFireTime(const QString &expr, const QDateTime &after);

    // 验证 cron 表达式是否合法
    static bool isValid(const QString &expr);
};
```

### 3.8 持久化

心跳配置存储在 Agent 工作空间：

```
~/.tmagent/identities/agents/{agentId}/
  heartbeat_config.json     # 心跳配置
  heartbeat_state.json      # 心跳状态（上次运行时间等）
  HEARTBEAT.md              # 心跳内容文件
```

定时任务存储在全局目录：

```
~/.tmagent/config/
  scheduled_jobs.json       # 所有定时任务定义
  job_runs/                 # 执行历史（按日期分文件）
    2026-02-21.jsonl
```

## 四、与现有系统的集成

### 4.1 与 AgentRuntime 集成

心跳触发时，通过 ChatService 调用 AgentRuntime 的 LLM 链路：

```cpp
// ChatService 中的心跳处理
void ChatService::onHeartbeatTriggered(const QString &agentId, const QString &reason) {
    auto *runtime = m_runtimes.value(agentId);
    if (!runtime) {
        runtime = ensureRuntimeForAgent(agentId);
    }

    // 读取 HEARTBEAT.md 内容
    QString content = MemoryManager::instance().readHeartbeatContent(agentId);
    if (content.trimmed().isEmpty() && reason != "exec") {
        emit AgentEventBus::instance().heartbeatSkipped(agentId, "empty-content");
        return;
    }

    // 构造心跳消息，注入主会话
    runtime->handleHeartbeat(content, reason);
}
```

### 4.2 与 AgentEventBus 集成

新增事件类型：

```cpp
// AgentEventBus 新增信号
signals:
    void heartbeatEvent(const HeartbeatEvent &event);
    void schedulerEvent(const SchedulerEvent &event);

// 事件结构
struct HeartbeatEvent {
    QString agentId;
    QString reason;       // interval / exec / requested / retry
    QString status;       // triggered / completed / skipped / failed
    QString detail;       // 跳过原因或完成摘要
    QDateTime timestamp;
};

struct SchedulerEvent {
    QString jobId;
    QString jobName;
    QString agentId;
    QString status;       // fired / completed / failed
    QString error;
    QDateTime timestamp;
};
```

### 4.3 与记忆系统集成

心跳是记忆反思的天然触发点：

1. 心跳回调中可调用 `MemoryManager::reflectIfNeeded()` 触发记忆整理。
2. HEARTBEAT.md 中可配置"检查记忆健康度"作为心跳任务之一。
3. 定时任务可配置"每日记忆备份"。

### 4.4 与并发控制集成

复用现有的工具循环熔断策略：

1. 心跳触发的 LLM 调用受 `tool_loop_policy.json` 约束。
2. 如果用户正在对话（有活跃回合），心跳排队等待（HeartbeatWake 的 running 标志）。
3. 定时任务的 `sessionTarget: "isolated"` 在独立会话中执行，不阻塞主会话。

### 4.5 活跃时间窗口检查

```cpp
bool HeartbeatService::isInActiveHours(const ActiveHours &hours) const {
    if (hours.start.isNull() || hours.end.isNull()) {
        return true;  // 未配置则始终活跃
    }

    QDateTime now = QDateTime::currentDateTime();
    if (!hours.timezone.isEmpty()) {
        now = now.toTimeZone(QTimeZone(hours.timezone.toUtf8()));
    }

    QTime currentTime = now.time();

    if (hours.start <= hours.end) {
        // 不跨午夜：08:00 - 23:00
        return currentTime >= hours.start && currentTime <= hours.end;
    } else {
        // 跨午夜：22:00 - 06:00
        return currentTime >= hours.start || currentTime <= hours.end;
    }
}
```

## 六、里程碑规划

### H1：心跳基础闭环

目标：单个 Agent 的心跳周期唤醒可用。

工作项：
1. 实现 `HeartbeatConfig` 数据模型与 JSON 持久化
2. 实现 `HeartbeatWake` 请求合并器（QTimer + 状态机）
3. 实现 `HeartbeatService` 核心调度逻辑
4. ChatService 接入心跳触发 → AgentRuntime LLM 调用
5. HEARTBEAT.md 读取与空内容检测
6. 活跃时间窗口检查
7. AgentEventBus 接入心跳事件
8. 心跳配置 UI（信息设置页扩展）

验收标准：
- Agent 启用心跳后，按配置间隔自动触发 LLM 调用
- 活跃时间窗口外不触发
- HEARTBEAT.md 为空时跳过（exec 豁免）
- 心跳事件在右侧面板可见
- 用户对话期间心跳不中断对话

### H2：心跳增强

目标：重复抑制、手动触发、热加载。

工作项：
1. 重复消息抑制（24h 窗口 + 文本比较）
2. 手动触发入口（UI 按钮 + 工具命令）
3. 配置热加载（修改间隔/活跃时间即时生效）
4. 心跳状态持久化（`heartbeat_state.json`）
5. 心跳与记忆反思联动（心跳时触发 `reflectIfNeeded`）

验收标准：
- 24h 内相同回复不重复发送
- UI 修改心跳配置后无需重启即生效
- 应用重启后心跳状态恢复（不会立即重复触发）

### H3：定时任务基础

目标：Cron 定时任务可用。

工作项：
1. 实现 `CronParser`（5 段 cron 表达式解析）
2. 实现 `ScheduledJob` / `JobRun` 数据模型
3. 实现 `SchedulerService` 核心调度逻辑
4. 任务持久化（`scheduled_jobs.json` + `job_runs/*.jsonl`）
5. ChatService 接入定时任务触发
6. AgentEventBus 接入调度事件
7. 定时任务管理 UI

验收标准：
- 可创建 Cron 定时任务并按时触发
- 任务执行历史可查
- 任务支持启用/禁用/手动触发
- 应用重启后任务自动恢复调度

### H4：定时任务增强

目标：会话隔离、一次性任务、与群聊联动。

工作项：
1. `sessionTarget: "isolated"` 支持（创建独立会话执行）
2. 一次性任务支持（执行后自动禁用）
3. `agentTurn` payload 类型支持
4. 与群聊 MessageRouter 联动（群聊就绪后）
5. 任务模板（晨间简报、每日复盘等预设）

验收标准：
- isolated 任务在独立会话中执行，不影响主对话
- 一次性任务执行后自动标记为已完成
- 预设模板可一键创建

## 七、与路线图的关系

心跳与定时任务是**跨阶段能力**，不属于路线图中的单一阶段：

| 里程碑 | 依赖的路线图阶段 | 说明 |
|--------|-----------------|------|
| H1 | 当前即可启动 | 仅依赖 AgentRuntime + ChatService，已就绪 |
| H2 | 当前即可启动 | 依赖记忆系统（M4 已就绪） |
| H3 | 当前即可启动 | 独立能力，不依赖群聊 |
| H4 | 部分依赖阶段 3（群聊） | isolated session 可先行，群聊联动后置 |

建议执行策略：H1 → H2 → H3 → H4，与当前 M4 收口和群聊准备并行推进。

## 八、风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 心跳阻塞主线程 | UI 卡顿 | 心跳 LLM 调用复用现有异步链路，不引入同步等待 |
| 心跳与用户对话冲突 | 消息交错 | HeartbeatWake 的 running 标志 + 活跃回合检测 |
| Cron 解析复杂度 | 引入 bug | 优先使用成熟的 croncpp 库，或限制为简单子集 |
| 定时任务堆积 | 资源耗尽 | 全局并发预算控制，同一 Agent 同时只执行一个定时任务 |
| 应用未运行时错过任务 | 任务丢失 | 启动时检查 missed jobs，可选补执行 |

## 九、技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 心跳定时器 | `QTimer::singleShot` | 精确计算下次时间，避免 setInterval 漂移 |
| 请求合并 | 自实现 HeartbeatWake | 逻辑简单，无需引入外部库 |
| Cron 解析 | croncpp（header-only）或自实现 | 轻量，MIT 许可，无额外依赖 |
| 任务持久化 | JSON + JSONL | 与现有持久化方案一致（Markdown + JSONL） |
| 事件总线 | AgentEventBus 扩展 | 复用现有基础设施 |
| 并发控制 | 现有工具循环熔断 | 不引入新的并发机制 |
