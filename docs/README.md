## 5. 冲突处理规则

1. 规范层（00） vs 方案层（10）冲突：以规范层为准。
2. 方案层（10） vs 调研层（20）冲突：以方案层为准。
3. 调研层（20）仅提供候选思路，不直接作为开发指令。
4. 调研层内部以 `docs/20_调研/22-调研结论汇总.md` 作为默认入口。
5. 执行层（30）是唯一“当前在做什么”的展示入口。
6. 轨道注册表只登记长期轨道，不替代主线状态。
7. 验收记录只记录“实现验收 / 发布验收”结论，不替代主线状态。

---

## 6. 维护要求

1. 新文档必须放入对应层级目录，不允许直接平铺到 `docs/` 根目录。
2. 新文档命名使用前缀编号：`NN-文档名.md`。
3. 发生路径变更时必须同步修正文内链接。
4. 失效文档移动到 `docs/90_归档/`，并在文首标记 `状态：archived`。
5. 方案层文档不得继续记录“当前进展/已完成/阶段收口”等执行状态。
6. 新功能、新流程、新资料、新想法先登记 `docs/30_执行/31-候选变更池.md`，不得直接打断当前主线。
7. 每次功能或流程改造完成后，必须按 `docs/00_规范/03-文档执行闭环规范.md` 与 `docs/00_规范/04-变更准入与关门清单.md` 回写状态和验收。
8. `docs/30_执行/30-当前执行主线.md` 只保留当前状态；历史长记录统一迁入 `docs/30_执行/36-执行日志归档.md`。
