# 候选变更池

> 状态：active（待评估）
> 目的：承接新想法，避免打断当前主线执行。

---

## 一、使用规则

1. 所有新想法先登记在这里。
2. 候选项状态仅允许：`new` / `accepted` / `rejected` / `deferred`。
3. 只有 `accepted` 项才能进入下一迭代主线。
4. 调研层文档不自动进入候选池，需先转换为可执行变更条目。
5. 测试中发现问题可作为“插单”登记，按优先级分为 `P0` / `P1` / `P2`。
6. `P0` 可直接打断主线执行；`P1` 可插入当前迭代；`P2` 默认下一迭代处理。
7. 插单执行前必须补齐“现象、复现步骤、影响范围、验收标准”四项。
