# TmAgent 变更准入与关门清单

> 状态：active（规范，执行门禁清单）
> 目的：把“新增资料 / 新功能 / 新流程 / 插单修复”的进入条件和关闭条件固定下来，避免靠口头约定推进。

---

## 一、适用场景

以下任何一种变更发生时，都必须使用本清单：

1. 新增资料文档
2. 新增功能
3. 新增流程治理项
4. 插单修复
5. 影响阶段判定、验收口径或状态真源的改动

---

## 二、准入清单（进入执行前）

以下项目必须全部明确：

- [ ] 已登记到 `docs/30_执行/31-候选变更池.md`
- [ ] 已标明任务类型：`doc / feature / architecture / process`
- [ ] 已标明所属产品阶段
- [ ] 已标明所属执行轨道
- [ ] 已标明影响层级：`00 / 10 / 20 / 30`
- [ ] 已标明是否允许插单
- [ ] 已标明验收出口文档
- [ ] 已判断是否需要新增专项方案
- [ ] 已确认不会让方案层承担实时状态真源

任一项为空，不得进入主线。

---

## 三、实施清单（执行中）

执行过程中必须持续满足：

- [ ] 当前状态只写在执行层
- [ ] 方案层不写“当前做到哪”
- [ ] 若主线改变，已同步更新 `30-当前执行主线.md`
- [ ] 若长期轨道状态改变，已同步更新 `35-轨道注册表.md`
- [ ] 若发生插单，已先登记候选池，再执行
- [ ] 若中断主线，已写明打断原因、影响项和恢复点

---

## 四、关门清单（宣称完成前）

宣称“完成”“通过”“切换下一主线”前，必须全部满足：

- [ ] 对应实现已落地
- [ ] 验收记录已创建或已更新
- [ ] 已明确 `实现验收` 结论
- [ ] 已明确 `发布验收` 结论
- [ ] 当前主线状态已回写
- [ ] 旧口径已清理或已迁移到归档
- [ ] 若主线文档过长，历史长记录已迁入 `36-执行日志归档.md`

---

## 五、阶段切换额外门禁

从一个产品阶段切到下一阶段前，必须满足：

- [ ] 当前阶段的 `发布验收` 已通过
- [ ] 下一阶段的进入门禁已明示
- [ ] 当前主线和轨道状态没有冲突
- [ ] 不存在两个文档同时声称自己是“当前状态真源”

---

## 六、使用规则

1. 本清单是规范层硬门禁，不是建议。
2. 若实际代码和文档冲突，以可验证事实作为临时准绳，但必须在当日回写修正。
3. 后续若引入自动检查脚本，应以本清单为准，不得另起一套规则。
