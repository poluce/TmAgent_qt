# TmAgent 文档执行闭环规范

> 状态：active（规范，执行流程闭环）
> 目的：定义“需求进入 -> 准入 -> 方案 -> 实施 -> 验收 -> 归档”的统一流程，避免文档与代码长期漂移。

---

## 一、适用范围

适用于 `docs/` 下所有 active 文档，尤其是：

1. `docs/00_规范/00-项目愿景与产品规划.md`
2. `docs/00_规范/01-Qt技术约束与前提条件.md`
3. `docs/00_规范/02-愿景落地路线图.md`
4. `docs/00_规范/04-变更准入与关门清单.md`
5. `docs/10_方案/10-架构升级设计方案.md`
6. `docs/30_执行/30-当前执行主线.md`
7. `docs/30_执行/31-候选变更池.md`
8. `docs/30_执行/35-轨道注册表.md`

---

## 二、文档职责边界

### 2.1 规范层（00）

只负责：

1. 产品边界
2. 技术红线
3. 路线图阶段
4. 变更准入和关门规则

不负责：

1. 记录当前进度
2. 记录当前主线
3. 记录临时执行状态

### 2.2 方案层（10）

只负责：

1. 目标设计
2. 实现边界
3. 迁移策略
4. 风险与门禁

不负责：

1. 记录“当前做到哪”
2. 记录“已完成/阶段收口”
3. 替代执行层承担状态真源角色

### 2.3 调研层（20）

只负责：

1. 原始输入
2. 可采纳结论
3. 候选思路

不直接作为开发指令。

### 2.4 执行层（30）

只负责：

1. 当前主线状态
2. 候选事项准入
3. 长期轨道登记
4. 验收结论
5. 历史长记录归档

其中：

1. `30-当前执行主线.md` 是唯一“当前在做什么”的状态真源。
2. `31-候选变更池.md` 是唯一“新事项如何进入系统”的准入入口。
3. `35-轨道注册表.md` 只登记长期轨道，不替代主线状态。
4. `32/33/34-验收记录.md` 只记录验收结论，不替代主线状态。
5. `36-执行日志归档.md` 只保存历史长记录，不承担当前状态。

## 三、执行闭环（从哪儿到哪儿）

### 阶段 A：需求进入

输入来源：

1. 用户反馈/评审意见
2. 线上问题与日志分析
3. 新能力规划（如群聊、记忆、技能）
4. 流程治理和文档治理需求

输出产物：

1. 一个清晰的问题定义（目标、边界、非目标）
2. 一个初步验收口径
3. 一条候选事项登记

### 阶段 B：规范对齐

必须先对齐：

1. 愿景边界：`docs/00_规范/00-项目愿景与产品规划.md`
2. 技术硬约束：`docs/00_规范/01-Qt技术约束与前提条件.md`
3. 阶段门禁：`docs/00_规范/02-愿景落地路线图.md`
4. 准入清单：`docs/00_规范/04-变更准入与关门清单.md`

输出产物：

1. 所属产品阶段
2. 所属执行轨道
3. 影响层级判断（00/10/20/30）

### 阶段 C：方案定义

主执行方案唯一入口：

1. `docs/10_方案/10-架构升级设计方案.md`

专项方案只做补充，不可覆盖主方案与规范。

输出产物：

1. 方案或专项方案更新
2. 风险与回滚策略
3. 验收出口文档

### 阶段 D：准入与实施

执行要求：

1. 所有事项先进入 `docs/30_执行/31-候选变更池.md`
2. 被标记为 `accepted` 后，才可进入主线或轨道
3. 执行中状态只允许写入执行层文档
4. 先改主链路，再补专项细节
5. 同步最小测试与日志可观测点

输出产物：

1. 代码或文档变更
2. 当前主线状态更新
3. 轨道状态更新

### 阶段 E：验收回写

必须回写到文档：

1. 对应验收记录
2. 当前主线状态
3. 必要时更新轨道注册表

验收结论分两级：

1. `实现验收`
2. `发布验收`

规则：

1. 未完成完整构建/完整回归/必要平台验证时，不得写“发布验收通过”。
2. 阶段切换、主线切换、对外宣称完成，必须以“发布验收”结论为准。

### 阶段 F：归档治理

规则：

1. 被替代内容移入 `docs/90_归档/`
2. 历史长记录移入 `docs/30_执行/36-执行日志归档.md`
3. 活跃文档中必须写清替代关系或引用关系

---

## 四、强制规则

1. 方案层不得继续承担实时状态真源职责。
2. 执行层不得复用路线图阶段号表达其他横向轨道里程碑。
3. 所有新增事项必须先过 `04-变更准入与关门清单`。
4. 主线文档必须保持短小，只保留当前状态、门禁、阻塞和下一步。
5. 历史长流水不得无限堆积在主线文档中。

---

## 五、本项目当前推荐口径

1. 决策顺序：`00 -> 01 -> 02 -> 04 -> 10 -> 30`
2. 执行顺序：`候选池 -> 主线/轨道 -> 验收记录 -> 归档`
3. 文档变更顺序：`先改规范引用 -> 再改方案内容 -> 最后改执行状态与归档`
4. 当前状态只看：`30-当前执行主线.md`
