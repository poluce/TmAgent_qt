## 二、共识结论（已采纳）

### 2.1 架构侧

1. 当前核心风险是“单体 God Object + 隐式状态机 + 双轨历史”。
2. 必须以 `Identity / Session / Message` 为中心做职责分层。
3. 会话主键必须脱离 UI 行号，统一用稳定 ID。
4. 并发与取消语义必须统一，支持插话和回合中断。
5. 必须引入全链路追踪（`trace_id`）和结构化事件日志。

### 2.2 记忆侧

1. Markdown 记忆文档应作为主真源，便于审查和人工修正。
2. 记忆与会话历史必须分离，避免互相污染。
3. 记忆闭环应是 `Retain -> Recall -> Reflect`，分阶段实现。
4. 检索索引（SQLite/FTS/向量）应是派生层，可重建。
5. 删除会话不等于删除身份记忆；删除助手才删除其长期记忆。

## 三、分歧点与统一取舍

### 3.1 关于存储主轴

分歧：是否直接用 SQLite 作为唯一存储。

统一取舍：

1. 当前阶段不以 SQLite 为主真源。
2. 先保证 Markdown + JSONL 稳定，再接入 SQLite 派生索引。

### 3.2 关于改造节奏

分歧：一次性重构 vs 渐进式迁移。

统一取舍：

1. 采用渐进式迁移。
2. 先修主链路问题，再补高级能力。

### 3.3 关于调研文档角色

分歧：调研报告是否可直接作为开发指令。

统一取舍：

1. 调研文档只提供候选思路。
2. 开发执行必须回到方案层和规范层文档。
